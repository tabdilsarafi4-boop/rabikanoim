# پنل مشتری روبیکا — نسخه مستقل

این بسته فقط شامل **پنل مشتری و فایل‌های لازم برای اجرای ربات روبیکا** است. پنل مدیریت، فایل PHP مدیر، رمز مدیر و سرویس مدیر در این بسته وجود ندارد.

## محتویات
- `panel.py`: رابط پنل مشتری
- `bot.py` و `login_worker.py`: منطق ربات و ورود/اتصال حساب روبیکا
- `supabase_store.py`: دریافت تنظیمات هوش مصنوعی از Supabase
- `Dockerfile`: ساخت ایمیج پنل مشتری برای Railway یا سرور جداگانه
- `schema.sql`: ساخت جدول تنظیمات مرکزی در صورت نیاز

## راه‌اندازی روی Railway
1. فایل‌های این بسته را در ریشه مخزن GitHub قرار بده؛ `Dockerfile` باید در همان ریشه باشد.
2. مخزن را به Railway وصل کن و Deploy بزن.
3. در بخش **Variables** متغیرهای موجود در `env.example` را با مقادیر واقعی اضافه کن؛ خود فایل `.env` را لازم نیست در GitHub آپلود کنی.
4. اگر برنامه برای ذخیره‌سازی پایدار از `/data` استفاده می‌کند، در Railway یک **Volume** بساز و آن را به مسیر `/data` متصل کن. دستور `VOLUME` عمداً از Dockerfile حذف شده، چون Railway مدیریت Volume را از پنل خودش انجام می‌دهد.
5. اگر جدول `public.ai_settings` هنوز در پروژه Supabase ساخته نشده، محتوای `schema.sql` را در SQL Editor اجرا کن.

برنامه روی پورت تنظیم‌شده با `PANEL_PORT` اجرا می‌شود؛ در Railway مقدار `PANEL_PORT` را معمولاً روی متغیر پورت ارائه‌شده توسط پلتفرم تنظیم نکن مگر اینکه برنامه آن را پشتیبانی کند، و مطمئن شو سرویس روی `0.0.0.0` گوش می‌دهد.

## امنیت مهم
کلید `SUPABASE_SERVICE_ROLE_KEY` محرمانه است و باید فقط در فایل محیطی سرور باشد. اگر مشتری به فایل‌ها یا دسترسی سرور دسترسی دارد، ممکن است بتواند این کلید را استخراج کند؛ برای سرویس تجاری چندمشتری، راه امن‌تر این است که کلیدهای AI و دسترسی Supabase فقط روی سرور خود مدیر باقی بمانند و ربات از API واسط استفاده کند.

این بسته پنل مدیریت ندارد و تنظیمات مرکزی AI را خودش ویرایش نمی‌کند؛ فقط تنظیمات ذخیره‌شده در Supabase را می‌خواند.
